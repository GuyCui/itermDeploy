# Mihomo 自动管理

**平时正常上网即可，不用每天运行命令，也不用手动更新节点。**

```text
SublinkPro → 脚本更新本地节点文件 → Mihomo 使用节点联网
                    ↑                   ↑
             自动检查、下载测速 ──── 选择经过验证的节点
```

- **配置文件**管 DNS、国内外分流、TUN。
- **脚本**更新订阅，检查失效节点，比较下载速度，再选择节点。
- **Mihomo**处理手机、电脑、Docker 的实际网络流量。

## 哪些定时任务保留

| 项目 | 谁负责 | 当前做法 |
|---|---|---|
| 下载节点订阅 | 脚本 | 开机约 2 分钟后开始；每次完成约 10 分钟后再更新 |
| 故障检查与恢复 | 脚本 | 每轮完成约 15 秒后再次检查 |
| 下载速度比较 | 脚本 | 默认约 30 分钟一轮，有每日测速流量预算 |
| 节点健康/延迟检查 | Mihomo | 保留，供地区组等使用；这不是下载订阅 |
| 分流规则、GeoIP/GeoSite 更新 | Mihomo | 保留，与节点订阅无关 |

脚本接管后，`Airport_01` 是 `type: file`，没有订阅 `url` 和下载 `interval`。**不要把所有叫 `interval` 的配置都删掉。** [配置片段](examples/provider.fragment.yaml)仅用于对照，不能覆盖完整配置。

自动选择只管理 `Proxy-Auto` 和存在时的 `Docker-Auto`；地区、AI 等其他组仍按原配置运行。测速只比较本轮候选，不保证所有节点都可用或永远选中最快节点。

## 已经安装的人怎么用

通常什么都不用做。出问题时在 **Debian** 终端执行：

```bash
sudo mihomoctl check --no-source   # 快速检查当前节点、进程和定时器
sudo mihomoctl check               # 额外下载源订阅并比较，可能等待 120 秒
sudo mihomoctl sync --no-source    # 立即更新订阅，再检查
```

## 安装与维护

这是现有 Mihomo 旁路由的管理工具，不会从零安装 Mihomo 或配置路由器。安装有环境要求，也会重载网络配置；先看[安装、升级和回滚](docs/maintenance.md)。已经在运行这套脚本的机器不必为了收藏到 GitHub 再安装一次。

**自动更新节点 ≠ 自动升级脚本或 Mihomo 软件。** GitHub 用于保存和维护代码；`git pull` 只更新仓库副本，不会立即覆盖正在运行的服务。

仓库不保存真实订阅、控制密钥、节点缓存、状态或完整旁路由配置。
